Owner idea 2026-11-14, to make review easier ('where do I look?'). A small data-driven registry NEW_FEATURES = [{id, since, anchor (selector or control id), text, card}]. Each entry shows a pulsing dot plus a short callout on its control; tapping it or the control retires it (per-browser localStorage 'seen' set, wrapped in try/catch). Rules: (1) no flood: only features that land from now on, plus a one-time backfill for the cards currently in Needs Review; if the owner wants a flood, cap at 5-10 per session. (2) Review builds only (the dev artifact build and ?new=1), never the public build; the same mechanism may later feed first-run onboarding (4.1). (3) Lanes add one registry line per user-visible landing (id = card id, e.g. 'PD-142.38.s4'), and the REVIEW board post names the id; an edited feature reuses its id with a new revision to re-arm it. (4) A 'Seen all' control in the utility drawer, and a count of unseen items. Open design points: callout placement on phone (must not cover dice or the dock), behaviour for controls inside the collapsed drawer, anchors that move with the navigation redesign (anchor by data-feature attribute, not by class). Dependencies: build after nav slices 5/6/7 settle the control layout; index.html is edited by several lanes, so keep the registry in one block and the renderer small. Lane: settings (after slice 7), or a short dedicated slice.

## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Owner request 2026-11-13: during a game the normal mat total (#result, 54px sum + breakdown) conflicts with the game readout or is irrelevant, but the total is also the press-and-hold handle for the overhead check (#result .tot, holdTop). Reduce clutter by hiding it while a game runs and keep a clean way to look top-down.

Findings from the code (index.html): #result is absolutely placed at top:46px; .tot is the pointer handle (pointerdown -> holdTop(true), release/cancel/blur -> holdTop(false)); the t key also calls holdTop; holdTop only acts while rolling, adds .peek to #result and body (body.peek hides tools/shelf/name/hint; #result fades to .18).

Proposal: (1) add body.game while a game runs (set/cleared where the game starts/ends); under it hide #result .tot and #result .brk entirely (display none, no pointer events). Keep #result .relean (re-lean button), since leaning dice still matter. (2) The game's own status strip (the ~48px strip from PD-142.30) becomes the press-and-hold handle for the overhead view: pointerdown on the strip status text -> holdTop(true), release/cancel/blur -> false; same gesture as before, no new control. Add a small eye/overhead glyph at its left edge as the affordance and a title/tooltip 'hold to look from above'. (3) The t key keeps working on desktop. (4) While topHold, the strip and any bet/tile row fade like #result does (add them to the body.peek rules) so the dice can be read. (5) Games whose rules use the roll sum (Craps, Shut the Box, Bunco, Ship Captain and Crew) show their sum in the strip text, so nothing is lost. (6) Fallback if the strip handle conflicts with buttons in the strip: top-down only via the t key plus a dedicated small overhead button in the corner stack (same style as the bag button) shown only in game mode.

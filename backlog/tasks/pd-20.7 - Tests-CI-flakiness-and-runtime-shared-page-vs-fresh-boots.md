## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
CI on the 4-core runner takes ~18 min and 1-2 tests go flaky. Signature: a fresh-page boot (app.open) in a worker whose browser also holds the shared paused page hangs at page.goto/waitForFunction, and once the _sharedPage context hung on close. Ideas: split Playwright projects so state-only specs (shared fixture) and fresh-page specs never share a browser; or close the shared context when a worker moves to fresh-page specs; check whether the paused page still holds GPU/audio work (AudioContext from rolls). Also consider a lighter boot for logic tests and measuring per-test time on the runner. Local repro: docker run --cpus=4 (see PD-20.1 notes).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Root causes found on a 4-CPU Docker repro (CI settings):
1. GPU-accelerated 2D canvas on SwiftShader: atlas/filigree/substrate drawing ran in software GL. One filigree build blocked the main thread ~60 s (CPU profile: all native '(program)' time). Fix: --disable-accelerated-2d-canvas in playwright.config.mjs and probe.mjs.
2. In a browser that holds the paused shared page, the next new page's getContext('webgl2') blocks ~18 s (measured: gl> at 287 ms, gl< at 18091 ms; alone <100 ms). Fix: projects fast-state (STATE_SPECS = logic, physics; shared page only) and fast-ui (fresh pages: smoke, new boot.spec.mjs with undo + determinism). Separate workers, so separate browsers. Fixtures throw if mixed. --project='fast-*' runs both.
Result, 4-CPU Docker, retries 0: before 20.0 min, 3 failed; after 6.8 min, 48/48 passed. Host npm test: 2.5 min, 48/48.

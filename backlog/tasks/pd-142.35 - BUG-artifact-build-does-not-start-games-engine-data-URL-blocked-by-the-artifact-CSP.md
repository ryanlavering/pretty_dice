## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Owner report 2026-11-13 from phone: the 'Pretty Dice v4 Dev' artifact stays on 'Starting' then shows 'Pretty Dice could not start' (No progress for 10 s, last step: Starting).

Root cause (reproduced locally): scripts/build-static.py --artifact puts games/*.js into the import map as data: URLs ('pd-games', 'pd-games/<file>'). Under a CSP that only allows the CDNs for script-src (claude.ai artifacts), Chromium refuses 'Loading the script data:text/javascript...' so the main module's static import of 'pd-games' fails and nothing runs. Repro: serve dist/pretty-dice-artifact.html with header Content-Security-Policy: script-src 'unsafe-inline' https://cdn.jsdelivr.net https://cdnjs.cloudflare.com (a node/playwright script that does this is at /tmp/claude-1000/-home-ryan/8682c4b4-6830-46d6-9987-f44adc962d1a/scratchpad/csptest.mjs; copy it into tests/ or scripts/). It also blocks a blob: worker; check whether anything else in the artifact boot needs a blob: worker and degrade gracefully.

Fix direction: in the --artifact build, do NOT use data: URLs for scripts. Bundle games/*.js into the single inline <script type=module> (strip import/export between engine files, wrap in an IIFE or object, and have index.html's engine import read from it), or generate the main module with the engine concatenated above it. Keep the dev (served) and offline (file://) builds working. Add a regression test: load dist/pretty-dice-artifact.html with the CDN-only CSP above and assert window.__ready and a game starts (@slow). Then tell the integrator so the artifact can be republished.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fix: scripts/build-static.py --artifact now inlines the engine (games_bundle(): each games/*.js wrapped in an IIFE, imports rewritten to a local map) in place of the main module's `import * as GAMES from 'pd-games'`; no data: script and no games entries in the artifact import map. The offline (file://) build keeps the data: URL import map, and dev is unchanged. The blob: watchdog worker is created in a try/catch and post() is guarded on L.worker, so a CSP that blocks it only costs the hang report (verified: the artifact boots under the CSP with the worker refused). Regression test: tests/artifact-csp.spec.mjs (serves the artifact with a CDN-only script CSP, answers the CDN requests from vendor/, checks __ready, no CSP refusal other than the worker, and starts a Yahtzee game). A new import of another pd-games path in index.html must keep the exact marker `import * as GAMES from 'pd-games';` or the build asserts.

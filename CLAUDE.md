# Pretty Dice

Single-file Three.js prototype (`index.html`, no build). Serve with `python3 -m http.server 8123`.

- Tasks live in `backlog/` (backlog.md, prefix `pd`). Check `backlog/tasks` before starting; update status as you go. Landing a feature includes moving its Review Complete cards to Done once the work is on main (not just an integration branch). Add `PATH=$HOME/.local/opt/node/bin:$HOME/.local/npm-global/bin:$PATH` to use the `backlog` CLI.
- **v4 branch test cadence (owner, 2026-11-13):** write and run tests for each feature (its own spec or `@quick` tests), but do not run the quick tier before every push or the full suite per card. Full `npm test` runs at batch checkpoints and before release; remote CI runs as normal. Bug fixes still get a regression test. This overrides the per-push rule below while on `v4`.
- Tests: Playwright suite in `tests/` (design: `docs/design/testing.md`). `npm install` once, then `npm test` (host; skips screenshot baselines) or `npm run test:docker` (pinned image; the only place visual baselines are made/compared). `npm run test:quick` is the fast tier (about 50 tests: physics, logic, bag model, bag sets, plus tests tagged `@quick`; tests tagged `@slow` in those files are left out): run it before every push. Run the full `npm test` before moving a card to Needs Review and at milestones. Tag a new cheap model-level test `@quick` (put `@quick` in its title); tag a test that boots a page per test and takes 20 s or more `@slow`. Test scripts take a machine-wide lock (`scripts/with-test-lock.sh`, `/tmp/pretty-dice-tests.lock`) so runs from several sessions queue instead of overloading the CPUs: always go through `npm test` (pass file filters after `--`), never a bare `npx playwright test`, set `PD_LOCK_NOTE="why/what you need"` so others can see it, check `npm run test:lock` to see who holds the lock and who is waiting, and don't kill a run that isn't yours; every bug fix gets a regression test. Drive the app through `window.__pd` (pause/renderOnce/setView/simRoll/memory + live state getters); `?seed=N` makes looks and rolls reproducible. Ad-hoc checks: `node scripts/probe.mjs 'pd.simRoll()'`.
- Remaining legacy hooks (`?test=atlas|models`) move into the visual specs with PD-20.2; don't add new `?test=` hooks, write a spec. Physics/state-only specs use the `shared` fixture (one booted page per worker, `shared.reset(seed)` per test) because booting dominates test time. `?shape=`, `?sub=`, `?radius=` preselect a look.
- Settings persist in localStorage (`prettydice.v1`); clear it when testing defaults.
- Libraries: loaded from the CDN with a fallback to `vendor/` (see `vendor/README.md`). `python3 scripts/build-static.py` makes the single-file offline build in `dist/` (git-ignored). Keep the `<!--BOOTSTRAP-->` markers in `index.html`; the build script replaces that block. Test offline with chrome flag `--host-resolver-rules="MAP cdn.jsdelivr.net ~NOTFOUND, MAP fonts.googleapis.com ~NOTFOUND, MAP fonts.gstatic.com ~NOTFOUND"`.
- Sound engine, sample sets and the tuning tool: `sounds/README.md`. Tune at `/tools/sound-audition.html` (served from the repo); `tools/sound-audition.html` mirrors the hardness model in `index.html`, keep them in step.
